# Verdict devnet v1.3

The explicit M3 profile and [v1.3 spec](../../docs/devnet-verdicts-v1.3.md)
add node-local verdict verification, settlement and deferred native rewards.
The stub is a deterministic protocol test adapter, not a proof verifier.
The devnet has no bridge; its minted native units have no L1 backing.

`l2-genesis-v1.3.json` is the v1.2 allocation plus the STOP verdict sink
`0x42000000000000000000000000000000000000b3`. Its tracked stdlib generator
first refuses an existing allocation at that address. Reproduce/check with
`python3 -I scripts/devnet/generate_m3_genesis.py [--check]`.

`scripts/devnet/prepare_m3_devnet.py --gate-binary BIN --out NEW_DIRECTORY`
creates the active M3 config, authenticated host-specific original/fixed stub
descriptors, fork table, placeholder artifacts and reset genesis. The gate
identity binds the binary and source release, so replicas use the same build
artifact and descriptor bytes. Gate binaries are not embedded in fixtures.
The pure `system-v1.3.json` and `service-void-v1.3.json` vectors retain their
synthetic gate identity; they are not active network descriptors.

Live recordings are generated by the tracked `m3_devnet` integration test with
explicit `BOOLE_DEVNET_OP_RETH`, `BOOLE_DEVNET_ANVIL` and `BOOLE_DEVNET_GATE`
paths. Build the supervisor first with an absolute `CARGO_TARGET_DIR`. The
existing M1 client pins are checked before execution. Each disposable run uses
loopback only, independent verify replicas and forced per-block persistence.
The test genesis additionally funds the public test user and installs a reverting
measurement payee; both allocations are included in each recording. The test
config uses the public test pool signing key. Neither addition is a production
allocation or activation.

Set distinct fresh candidate paths in `BOOLE_DEVNET_M3_MEASUREMENT`,
`BOOLE_DEVNET_M3_ROUND`, `BOOLE_DEVNET_M3_KERNEL_FIX`,
`BOOLE_DEVNET_M3_QUARANTINE_VOID` and `BOOLE_DEVNET_M3_QUARANTINE_RECHECK`.
Run the measurement test first, then the I9–I12 tests. Outputs are written only
after A/B/C comparisons and strict log/process cleanup pass. Existing candidate
files are refused. The source, shared support, client and reset genesis hashes
are generated in tracked code, with the full config, descriptors, L1 and L2
genesis and per-height observations. No private metadata patching is required.

The 256-record gas probe uses a 256-record batch capacity; the active devnet
round config retains its ordinary 128-record capacity. Execution probes inject
extra deposits outside the consensus fold and are explicitly labeled that way.
Ordinary live rounds use independently computed verdicts and the actual fold.
Frozen v1.2 and earlier recordings remain unchanged and are superseded for the
v1.3 reset; their historical client revision remains required for replay.
