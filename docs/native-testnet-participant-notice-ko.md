# 네이티브 테스트넷 참여 전 기술 안내

상태: **준비용 초안 — 현재 공개 참여를 모집하거나 네트워크를 가동하는 안내가 아닙니다.**
R1은 미완, R2는 미통과, R3는 미착수입니다. 현재 프로그램은 loopback 주소만 허용합니다.
이 문서는 기술적 범위·손실·복구 한계를 알리는 안내이며 법률 약관, 면책 계약, 투자 안내나
출시 승인에 해당하지 않습니다. 실제 외부 참여 전에는 해당 릴리스·운영 범위와 필요한 별도
검토 및 승인을 확정해야 합니다.

## 무엇을 시험하나요?

`boole-native-testnet-1`에서 실제 해시 작업과 소유자 서명을 검증한 테스트 블록·송금·잔액을
시험합니다. 단위는 `tBOOLE`, 소수점은 8자리입니다. 테스트넷 발행 상한은 10억이며,
처음 블록 보상은 5만, 1만 블록마다 반감, 최소 송금 수수료는 `0.00001 tBOOLE`입니다.
새 기본 보상은 생성 높이 + 10부터 쓸 수 있고 수수료는 블록 생성자에게 갑니다.
60초는 목표 간격일 뿐 실제 생성 속도·보안성·처리 성능을 보장하지 않습니다.

테스트 코인에는 실제 금전 가치나 미래 메인넷 토큰·보상·잔액 이관 권리가 부여되지 않습니다.
기존 개발 포인트, 검증 영수증, legacy 네트워크 잔액과도 다릅니다. Useful-work 추가 보상은
꺼져 있으며, 이번 기본 송금 시험에 유료 모델/API 실행 권한이 포함되지 않습니다.

## 참여 범위와 신뢰 경계

- 초기 참여는 운영자가 별도로 확인한 노드 공개키 목록을 사용합니다. 익명 자동 가입,
  처음 본 키 자동 신뢰, 예상치 못한 키 교체는 하지 않습니다.
- 피어의 신원을 확인했어도 그 피어의 블록·잔액·작업량을 그대로 믿지 않습니다. 각 노드가
  서명과 블록·원장 규칙을 다시 검증합니다. 암호화 통신도 악성 데이터나 지연을 없애지는 않습니다.
- 초기 운영 RPC는 내 노드의 로컬 전용입니다. 공개 API, 프록시·터널, faucet, 원격 지갑
  대행 서비스는 이 범위에 없습니다. 외부 P2P도 구현·검증·승인 전에는 열지 않습니다.
- 세 프로세스가 같은 개발 Mac에서 통과했다고 해서 독립 운영자·실제 인터넷 환경·다른
  장비·공개 릴리스에서 검증된 것은 아닙니다.

## 실제로 생길 수 있는 일

- 프로그램 오류, 네트워크 분리, 저장장치 문제, 키·암호 분실, 잘못된 운영 때문에 테스트
  잔액이나 접근 가능성을 잃을 수 있습니다. 재편으로 이미 보였던 거래가 미확정으로 돌아갈 수
  있으며 `confirmed`도 최종 확정을 뜻하지 않습니다.
- 송금 응답이 늦거나 끊겨도 뒤에서 처리가 끝날 수 있습니다. 새 송금을 만들어 보상하려 하지
  말고 저장한 서명 파일과 같은 거래 ID로 상태·nonce를 먼저 확인하세요.
- 저장 한도, 대기열, 요청·연결·피어 제한과 전체 재생 비용이 있습니다. 큰 개발 시험에서는
  재시작 재생에 약 1분이 걸렸지만 내 장비의 시간 보장이 아닙니다. 한도를 올리거나 파일을
  지워서 오류를 없애지 마세요.
- 공개키·거래 서명·수신자·금액·연결 주소로 활동이 드러날 수 있습니다. 통신 암호화는
  모든 메타데이터를 숨기거나 테스트 장부를 비공개로 만들지 않습니다.

## 키와 복구 자료를 구분하세요

| 자료 | 역할과 주의점 |
|---|---|
| 암호화 소유자 지갑과 별도 암호 | 송금·블록 소유자 서명에 사용합니다. 모든 사본 또는 암호를 잃으면 이 기능으로 복구할 수 없습니다 |
| 암호화 지갑 백업과 독립 보관한 공개 주소 | 새 경로에 복원한 뒤 주소가 정확히 같은지 확인합니다. 백업 복원은 키 교체가 아닙니다 |
| 별도 통신 개인 키 | 피어 TLS 신원입니다. 현재 암호화되지 않은 0600 파일이며 지갑·보상 키와 다릅니다. 장부 아카이브에 포함되지 않습니다 |
| 서명된 outbox 파일 | 같은 거래 ID를 조회·재제출하는 원본입니다. 개인 키는 아니지만 거래 내용을 드러내고 재전송될 수 있습니다 |
| 정본 블록 아카이브와 별도로 확인한 head | 새 디렉터리에서 전체 검증하여 장부를 복구합니다. 대기 거래·지갑·암호·통신 키·피어 설정은 포함되지 않습니다 |

암호·seed·개인 키·vault/backup 파일 내용을 채팅, 이슈, 로그나 지원 요청에 붙이지 마세요.
서명기에 지정한 실행 파일과 호스트 자체는 비밀을 다루는 신뢰 경계입니다. 파일 권한과
암호화 지갑만으로 악성 관리자·호스트로부터 안전해지는 것은 아닙니다.

문제가 생기면 해당 작업을 멈추고 원본을 보존한 다음
[운영 복구 절차](native-operator-recovery-runbook.md)를 따르세요. 원본 한 벌에 수리하거나
lock/journal을 삭제하지 마세요. `native diagnostics` 성공은 원장 준비 상태를 확인한 것이
아니고, `inspect-transfer` 성공은 현재 잔액·만기·송금 확정을 확인한 것이 아닙니다.

실제 참여 전 확인할 항목은 [출시 준비 체크리스트](native-testnet-readiness.md)입니다.
정확한 릴리스/독립 신뢰 루트, 네트워크·genesis, 승인된 피어 공개키, 지원 장비, 운영 중단·사고
연락 담당, 백업·복구 확인, 기간·데이터 한도와 본인이 허용한 채굴·테스트 송금 범위가 필요합니다.
현재 이 문서에 실제 참여자의 동의나 공개 가동 승인이 기록되어 있지는 않습니다.
